# 玩家藏牌接口模拟 v0.3

运行 python src/player_demo.py。旧玩法 python src/main.py 继续可用。

本版由一名测试人员在一个终端模拟 B 的登记/揭牌、D 的提问/猜测和玩家的回答。
没有自动识牌、自动搜索或物理动作，也不代表整机已完成。

## 手动流程

输入“登记”，在不回显的提示中输入 7，回车，再输入“确认”。
之后依次输入：大于5、确认、回答是、确认、猜测7、确认、揭牌7、确认。
预期：剩余六次，机器人获胜，核验假话次数零。

## 接口

PlayerHidesService 与 RefereeService 使用相同 handle(event)、public_state() 接口与请求去重规则。
propose 的 kind 增加 register、yes、no、reveal；分别为私密登记、玩家回答是、玩家回答不是、揭牌。
register/reveal 的 number 为 1～10；yes/no 为 null。submit 为 D 的最终猜测。
确认和取消沿用 pending_id、version。
register 必须通过后续私密适配层输入与确认。本模拟不提供身份认证或真正分离的玩家设备。
公开快照中的登记待确认 number 始终为 null；不公开秘密值或对局中的假话次数。

## 状态与计次

registration → 私密登记确认 → strategy。
gt/lt/eq 提出并确认 → answer；yes/no 回答并确认 → 问答历史加一、扣一次 → strategy。
submit 确认 → reveal；reveal 确认后才核验结果。
取消回答仅取消尚未提交的回答，已经锁定的问题仍需回答，不能换题绕过计次。
七次问答后禁止普通提问，允许最终猜测。确认前不扣次数。

## 核验约定

本模拟设置最多两次“已确认但不一致”的揭牌：第一次提示重采集，第二次标记核验异常。
正式视觉接入后应由全组确认重试上限及人工复核流程。
揭牌一致时按登记值统计已确认回答的真假，超过一次记规则异常，不计普通输赢。
用户中途退出不公开秘密数字；无法核验可主动退出，尚未实现专用核验超时事件。
