# 开发协作

1. 从 main 创建任务分支，例如 `git switch -c feat/a-speech-parser`。
2. 每位成员先实现独立原型、正常和失败样例，再接 ROS。
3. 通过 PR 合并；接口变更由调用方与提供方共同检查。分支保护尚未配置。
4. 不修改厂商仓库远程地址，不把整个厂商工程复制进来。
5. 共用机器人由当次联调负责人统一更新和启动。更新前检查 git status，保存现场修改。

节点、话题和服务清晰命名；话题和服务使用小写下划线。参数从 launch/YAML 传入。回调不做长时间阻塞，等待有超时，异常保留日志。

原始图像、音频、对局记录放 runtime/（忽略提交）；不要提交凭据和秘密信息。选入仓库的测试样例须筛选。

每次提交说明运行命令、真实结果及未运行的检查。个人记录参考 records/TEMPLATE.md。

维护者姓名、邮箱与许可证目前是占位值，团队确认后替换。新增依赖及时补充 package.xml 和部署说明。
